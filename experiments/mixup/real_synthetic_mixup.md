更新：2026-10-28。状态：方案设计，以下 Mixup 结果尚未产生。工作位置为 ForecastPFN 仓库的 `experiments/`；已有样本级混合代码与结果说明见 [`sample_mixed/README.md`](sample_mixed/README.md) 和 [`sample_mixed/SCREENING_RESULTS.md`](sample_mixed/SCREENING_RESULTS.md)。

## 1. 已知结果与要回答的问题

现有样本级混合把真实窗口和模拟窗口分别放进 batch，未逐点合成新窗口。Exchange Rate 的 `0` 列、历史 96 天、预测 14 天上，5 个小模型、3 个 seed、9 个合成曝光比例共 135 次训练；按真实验证 RMSE 选比例后，Linear、DLinear、GRU 选出 0% 合成，MLP 和 Transformer 虽选出 12.5%，其测试 RMSE 相对各自 real-only 分别略高约 0.18% 和 0.04%。因此，该单数据集初筛没有显示稳定收益。七数据集完整网格尚无已完成证据，不能把这一结论推广到全部任务。

下一步检验：**让模拟模式作为真实窗口附近的结构化扰动，是否优于仅增加模拟样本？** 同时用真实—真实 Mixup 判断收益是否来自线性组合操作本身。这里借用 TSMixup 的凸组合思想；真实—模拟逐点组合是本实验改造，不是 Chronos 论文报告的默认数据配方。[Chronos §4](https://arxiv.org/html/2403.07815v1)

## 2. 数据与 Mixup 定义

沿用现有单变量任务、真实时间切分、合成生成器、观测值监督和 `L/H` 设置。只从当前任务的**真实训练窗口**抽取锚点；模拟窗口来自与该任务同频率、同 `L/H` 的固定合成池。验证与测试始终只用真实数据。

现有代码对每个真实或模拟窗口分别用**历史部分**计算均值和标准差，再以相同统计量标准化其历史和未来。因此主实验直接在这两个已标准化窗口上操作：

```text
Zr = concat(Xr_norm, Yr_norm)
Zs = concat(Xs_norm, Ys_norm)
Zm = λ Zr + (1-λ) Zs,  0 ≤ λ ≤ 1
(Xm, Ym) = split(Zm, L)
```

同一个 `λ` 用于完整的历史、未来及整个窗口，不能只混合 `X` 而保留真实 `Y`。主实验先使用固定 `λ`，不逐时间点抽权重。模型在标准化空间训练；真实验证/测试预测仍按**对应真实历史窗口**的均值和标准差反变换，绝不使用模拟窗口统计量反变换。

两个来源分别历史标准化使其数值量级可比，但不保证趋势、周期或相位相容。记录混合前后历史/未来的标准差、极值及自相关；若 `λ=0.5` 时振幅明显压缩，应把它视为可能的作用机制，不能直接归因于生成器增加了有益模式。第一版不做方差补偿，以免同时改变两个因素。

## 3. 主实验组与公平比较

每次更新固定 batch=64、2,000 updates、相同模型初始权重、优化器、学习率、真实训练池和真实验证集。每个 batch 先抽取 **64 个真实锚点**；其中 `p_aug=0.5` 的 32 个保持原样，另 32 个与伙伴窗口 Mixup。因此各组真实锚点曝光均为 128,000 次，区别仅在其中多少被增强。使用同一真实抽样流和同一增强位置，便于按 seed 配对。

| 组别 | 32 个增强位置的处理 | 用途 |
|---|---|---|
| Real-only | 原真实锚点 | 基准；64 个真实窗口照常训练 |
| Real–Real Mixup | 与另一真实训练窗口组合 | 分离线性组合本身的效果 |
| Real–Synthetic Mixup | 与同任务模拟窗口组合 | 检验模拟模式的增量价值 |
| Real + Synthetic pool | 现有样本级混合结果 | 方法参照；其真实曝光较少，解释时标明预算差异 |

主实验 `λ ∈ {0.9, 0.75, 0.5}`，两种 Mixup 都使用同一组权重与 `p_aug=0.5`。`λ=1` 等同 Real-only，无需重复训练。Real–Real 的两个窗口必须来自训练段；尽量避免锚点与伙伴为完全相同窗口，并记录重复配对率。模拟伙伴使用现有固定池与循环采样；不得从验证/测试段取窗口或根据测试表现筛选模拟样本。

**预算解释**：Mixup 组每步仍有 64 个真实锚点，但其中 32 个的值和标签已变化；“真实锚点曝光相同”不等于“原样真实样本曝光相同”。与现有 pool 组比较时，优先比较同模型、同 seed、同更新数，并单列其真实原样曝光数。若 Mixup 优于 pool，不能仅凭此证明 Mixup 形式更好，还需要下面的曝光消融。

## 4. 推进顺序

1. **实现前冻结协议**：复用 `utils/datasets.py` 的时间切分和历史标准化、`utils/synthetic.py` 的合成池、`utils/models.py` 的五模型、`utils/evaluate.py` 的真实尺度指标。新增独立的 Mixup 采样/训练入口和输出目录，不覆盖已有 `mixed_exchange` 结果。训练配置、数据与生成器代码摘要纳入运行签名。
2. **确定性检查与冒烟**：在 Exchange Rate、1 个 seed、Linear/GRU、Real-only 与两种 Mixup 的 `λ=0.75` 组上运行 50 updates。检查 `X/Y` 使用同一权重、窗口长度、有限 loss、梯度、真实来源只来自 train、固定 seed 可复现、真实验证/测试预测反变换正确。冒烟测试指标不用于选配置。
3. **Exchange 正式初筛**：5 模型 × 3 seed ×〔Real-only 1 组 + Real–Real 3 组 + Real–Synthetic 3 组〕= **105 runs**，每组 2,000 updates。现有样本级混合 135 runs 作为旁列参照，不重训也不混入新网格计数。若需要确认代码重构没有改变 real-only，先用同配置重跑一组并对照旧结果。
4. **扩展任务**：在真实验证集显示有希望、且代码复核通过后，按既有配置扩展到 ETTh1（日/小时频率对照），再到其余既定单变量任务。每个数据集独立训练与选模；完整七数据集 Mixup 网格为 735 runs（含 Exchange），不预设必须一次跑完。保持训练、验证、测试时间边界不变。
5. **针对性消融**：若初筛有收益，先对验证选中的模型/任务比较 `p_aug=0.25/0.75`，再考虑 `λ ~ Beta(α,α)` 等随机权重。若高强度组退化，优先做振幅/相位诊断；若 Mixup 优于旧 pool，则增加“相同真实原样曝光”的 pool/Real-only 对照，避免把曝光差异误判为方法优势。

## 5. 选择、指标与结论门槛

- 仍以每次运行**真实验证集原尺度 RMSE**选 `best` checkpoint，每 100 updates 检查一次，全部训练到 2,000 updates；同时保存 `final`。每模型/数据集的组别和 `λ` 由跨 seed 平均验证 RMSE 选择，测试集只用于一次性报告。
- 报告测试 MAE、RMSE、MASE、逐预测步误差、每 seed 的配对差值，以及相对同模型 Real-only 的变化；保留无需训练的 LastValue、ContextMean、SeasonalNaive。不同量纲数据集不直接平均原始 RMSE。
- 保存真实锚点、真实伙伴、模拟伙伴的采样次数与唯一窗口数；记录混合后 `X/Y` 分布、实际 `p_aug/λ`、生成器配置、时间切分、训练曲线和 checkpoint 步数。测试窗口高度重叠，3 个训练 seed 的标准差不能当作独立测试样本的置信区间。
- 只有 Real–Synthetic Mixup 在多个 seed 和任务上稳定优于 Real-only，且优于同强度 Real–Real Mixup，才支持“模拟模式提供额外有用信息”。只超过 Real-only 而未超过 Real–Real，结论应限于 Mixup 增强有效。Exchange 单任务微小差异只作为筛选信号，不作为普遍改善结论。

## 6. 实现落点与交付物

实现位于 `experiments/mixup/`，独立保存配置、训练入口与核验脚本；公共的数据、生成、模型和评估函数位于 `experiments/utils/`。`sample_mixed/engine.py` 在 batch 维拼接真实/模拟窗口，Mixup 入口则在抽取真实锚点后融合伙伴窗口。`utils/synthetic.py` 缓存的是分别标准化后的 `x/y`，可直接供主实验使用；若未来改为原始尺度先混合，必须另立协议和缓存签名。

产出：每次运行的配置/签名、训练日志、验证与测试指标、`best/final` 权重、测试预测数组、采样与 Mixup 诊断；汇总报告给出各模型/任务的验证选组、测试配对差值及与旧样本级混合的预算说明。核验脚本应从预测数组重算指标，并检查时间边界、组别网格、相同 seed 初始权重和实际增强比例。
